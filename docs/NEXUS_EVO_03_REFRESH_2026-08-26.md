# NEXUS-EVO-03：统一缓存、手动刷新与数据新鲜度

## 目标

在不改动 SHEIN 写入链路和业务状态机的前提下，统一 V2 页面切换与缓存复用行为：已缓存数据不会因路由重新挂载而重复拉取，数据只通过页面既有的手动刷新动作或业务成功后的定向失效更新。

## 本轮改动

- 商品草稿、单个建品、批量建品、发布批次、合规详情/草稿、模板中心和今日工作页面的 TanStack Query 全部设置 `refetchOnMount: false`。
- 发布批次中的发布回读查询与图片缩略图查询也采用同一策略，避免切换页面后重复读取 SHEIN 状态和重复请求媒体地址。
- 保留显式 `refetch()`、定向 `invalidateQueries()` 和发布/保存成功后的局部更新；没有关闭用户主动刷新，也没有让缓存过期数据伪装成实时数据。
- 新增回归合同，覆盖所有手动刷新工作区不使用 `refetchInterval` 且路由重新挂载不自动拉取；合同同时允许 `useQueries` 的明细查询拥有额外的同样保护。

## 影响范围与安全边界

- 不修改 SHEIN API 请求参数、签名、写入接口、发布幂等、合规判定和状态机。
- 不改变 EVO-02 已收敛的租户、用户、店铺 Query 作用域。
- 首次打开且没有缓存时仍会正常请求；只有“已有缓存 + 路由重新挂载”场景停止重复请求。
- 页面离开后不启用定时轮询；任务进度仍由既有任务状态机制负责。
