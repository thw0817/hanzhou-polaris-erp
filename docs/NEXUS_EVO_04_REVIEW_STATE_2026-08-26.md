# NEXUS-EVO-04：发布与审核状态机收敛

## 目标

把商品审核中心的当前状态、历史驳回、重新发起和店铺归档区分开，严格按 SHEIN 官方字段驱动状态，不让不确定字段把商品错误地从“待审核”移到“待核价”等其他阶段。

## 本轮收敛

- 审核事件的工作流阶段只接受明确的工作流字段（`workflow_stage`、`review_stage`、`stage` 等）或已归一化的官方审核字段；不再把通用 `status` 字段当作阶段依据。
- `audit_state=1` 在没有明确工作流阶段时保持“待审核”；`audit_state=2/3` 分别保持“已通过/已驳回”。未知或缺失字段继续显示待回读，不猜测。
- 保留当前发布版本优先规则：同一 SKC 重新发起后，以最新 SHEIN version 作为当前任务，旧版本驳回只进入历史计数，不覆盖当前版本；回读未完成时不回退到旧驳回状态。
- 所有读模型仍以租户、店铺作用域查询；本地归档只隐藏当前店铺的本地审核记录，不删除 SHEIN 商品或改写平台状态。

## 回归与门禁

- 新增回归：通用 `status=待核价` 不得把 `audit_state=1` 的审核记录误分类为待核价。
- 保留并继续验证重新发起、JSON 编码 SKC 列表、同版本重发、驳回次数和发布次数测试。
- 本阶段未改变 SHEIN 写接口、发布幂等、合规写入或权限校验；未部署云端。
