# HEF-01 / HST-01 / HWF-01 实施记录

本次补强按三条边界执行，所有平台状态和库存数值仍以 SHEIN 官方回读为准。

## HEF-01：事件订阅与动态提醒

- Webhook 已验签、去重、持久化并通过队列异步处理。
- 去重键现在包含租户与店铺范围；相同事件正文投递到不同店铺不会互相吞掉。
- 额度、合规失效、授权变更等业务投影在缺少租户/店铺范围时 fail-closed，只保留事件审计，不写入任何业务店铺状态。
- “今日工作”现在会把已落库的生产事件纳入手动刷新后的动态流，包括平台接收、审核状态、额度变更、合规变更、授权变更和库存预警。
- 动态流只读取当前用户可访问的租户/店铺范围，事件正文不直接展示；前端缓存键也包含当前租户与用户，退出或切换账号不会复用上一账号的今日数据。

## HST-01：销量、库存与经营分析

- 销量继续读取 `query-sku-sales`，库存和在途继续读取 `stock-query`。
- 总览新增实际库存、在途库存指标；缺少官方字段时保持空值，不用本地推算冒充平台数据。
- 缺失的官方库存字段与官方返回的 `0` 明确区分；未知库存不会生成“断货/补货”假预警，也不会被汇总成 0。
- 现有手动刷新、冷却、缓存和店铺隔离保持不变；经营快照缓存键包含租户/用户，非活动缓存有界回收，窗口聚焦和网络重连不会造成刷新风暴。

## HWF-01：审核与发布工作流

- 审核阶段别名在服务端统一归一化，`待审核`、`待核价`、`待寄样`、`待审版`、`待核样`、`待终审`、`已驳回` 不再因 SHEIN 返回中英文或 snake_case 别名而错分。
- 未知阶段不再被当作任意合法阶段，保持待同步/待确认。
- 发布幂等、结果未知保护、租户/店铺权限边界继续由现有协议和仓储层负责。
- 发布中心、审核中心和合规/经营数据查询统一采用租户 + 用户 + 店铺作用域的查询缓存，避免切店、切账号时出现旧状态串线。

验证：针对性回归测试通过（HEF/HST/HWF 缓存隔离、Webhook 去重/投影隔离、官方库存缺失字段、审核阶段归一化）；全量测试、V2 构建和发布审计将在本次部署前重新执行。本次未执行 SHEIN 写接口、未执行数据库迁移。
